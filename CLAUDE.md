# witcher-battle / Wastelands

## Суть проекта

Помощник ГМ для настольной ролевой игры **Wastelands** (постапокалиптический сеттинг).
Два назначения: **оцифровка листа персонажа** и **ведение боёв**.

Исторически репозиторий начинался как помощник ГМ для Witcher TRPG — весь код в
проектах `Witcher.*` относится к той, первой версии. Он не выброшен: боевой движок
(шаблоны существ, распределение попаданий по частям тела, броня, состояния,
критические эффекты, инициатива) со временем будет переработан и станет боевым
движком для Wastelands. Пока в коде встречается название "Witcher" и связанная
терминология — это наследие первой версии, а не текущая предметная область продукта.

## Модули

### Wastelands (новая часть — лист персонажа)

- `Witcher/Core/Wastelands.Core.Contracts` — сквозные контракты: пейджинг/
  сортировка (`IPagingParams`, `IOrderParams`, `PagedRequest`), `IUserContext`,
  `ErrorCode`, иерархия исключений (`BusinessLogicException` →
  `InvalidArgumentException` / `NotFoundException`; `WebException` →
  `BadRequestException` / `UnauthorizedException`).
- `Witcher/Core/Wastelands.Core.EfDataAccess` — обобщённые EF-абстракции:
  базовая `Entity`, `IBaseRepository` / `IBaseReadRepository`, `IFilter`,
  `PagedList`.
- `Witcher/Infrastructure/Wastelands.EfDataAccess` — реализации обобщённых
  репозиториев (`BaseRepository`, `BaseReadRepository`) и extension-методы
  для DI/веб-приложения.
- `Witcher/Services/Wastelands.Service/Wastelands.Service.Domain` — доменный
  слой: сущности `Character`, `User`, enum `Skill`, контракты сервисов и
  репозиториев, DTO, фильтры, модели запросов.
- `Witcher/Services/Wastelands.Service/Wastelands.Service.Infrastructure` —
  EF-конфигурации, `WastelandsDbContext`, миграции, реализации
  `CharacterService` / `UserService` / `PasswordService`.
- `Witcher/Services/Wastelands.Service/Wastelands.Service.MVC` — ASP.NET MVC
  хост: `CharacterController`, `LoginController`, exception filter/attribute,
  Razor-вьюхи.

### Witcher (первая версия — боевой движок, будет переработан)

- `Witcher/Witcher.Core` — домен шаблонов существ/боя и обработчики в
  CQRS-стиле (Requests/Handlers/Validators, MediatR-подобный паттерн).
- `Witcher/Witcher.Storage.Postgresql` — EF-конфигурация и миграции старой схемы.
- `Witcher/Witcher.MVC` — старые Razor-контроллеры/вьюхи + новый JSON-слой
  `Controllers/Api/*` (добавлен под SPA) + SignalR-хаб для боя в реальном времени.
- `Witcher/Witcher.UnitTest` — юнит-тесты обработчиков/сервисов первой версии.

### Фронтенд

- `witcher-frontend/` — React + TypeScript + Vite SPA, ходит в
  `Witcher.MVC/Controllers/Api/*` по JSON, SignalR — для экрана боя в реальном
  времени. Реализовано: аутентификация, список/вступление в игры, полный CRUD
  шаблонов существ, CRUD боёв, интерактивный экран боя. Экранов для персонажа
  Wastelands пока нет — это как раз то, что сейчас оценивает параллельная сессия.

## Статус

- Первая версия (боевой движок): шаблоны существ, распределение попаданий по
  частям тела, броня, состояния, критические эффекты, инициатива и порядок

- Wastelands: CRUD персонажа, логин/регистрация, блок из 7 характеристик

## Технологии

.NET (в `dev2-mvc` — .NET 10), EF Core + PostgreSQL, паттерн запрос/обработчик

## Доменный глоссарий

Описание правил и сущностей от автора. Часть сущностей существует параллельно
в старом (`Witcher.Core/DAL/Entities`) и новом (`Wastelands.Service.Domain`)
коде — это нормально на переходный период, конечная модель после переработки
описана здесь.

### Пользователи и игровые сессии
- **User** — пользователь приложения, данные для авторизации. Сущность общая
  для обоих проектов (Witcher и Wastelands).
- **Game** — партия в настольной ролевой игре (игровой стол). `CreatureTemplate`
  и `BodyTemplate` создаются мастером игры внутри конкретной `Game` — это его
  инструменты для создания монстров именно в этой партии.
- **UserGame** — связь пользователя с игрой (участие игрока в партии).
- **GameRole** — лишняя сущность. Права мастера игры не хранятся отдельно:
  они есть только у пользователя, создавшего игру.
- **UserAccount** — лишняя сущность.
- **UserGameCharacter** — лишняя сущность.

  > `GameRole`, `UserAccount`, `UserGameCharacter` — кандидаты на удаление при
  > переработке, самостоятельной смысловой нагрузки не несут.

### Персонажи и существа
- **CreatureTemplate** — шаблон НПС-противника. Создаётся мастером игры, чтобы
  затем на его основе порождать конкретные экземпляры существ для боя.
- **BodyTemplate** — шаблон тела: отображение тела существа и определение
  места попадания оружием. Содержит коллекцию `BodyTemplatePart`.
  - Каждая **BodyTemplatePart** — часть тела: сложность попадания в неё,
    модификатор урона при попадании, диапазон бросков кубика, дающих попадание
    именно в эту часть, и тип части тела (используется для определения вида
    критического эффекта при попадании).
- Когда `CreatureTemplate` привязывается к `BodyTemplate`, создаётся коллекция
  **CreatureTemplatePart** — стартовые параметры брони для этого типа существ
  по каждой части тела.
- При добавлении существа в бой на основании `CreatureTemplate` создаётся
  экземпляр **Creature** с коллекцией **CreaturePart** — текущее состояние
  конкретного существа (актуальная броня и т.д.) в текущем бою.
  - Пример: тип тела — «человек» (стандартные конечности). Шаблон существа —
    «разбойник» (стандартная броня разбойника). В бой добавлены два экземпляра
    на основе этого шаблона — «грязный разбойник» и «разбойник со шрамом»
    (индивидуализация одного шаблона в конкретных существах).
- **Character** — цифровой лист персонажа, сущность для персонажа игрока (не
  мастера). По сути соответствует `Creature`, но управляется игроком, а не
  мастером — опирается на стандартный `BodyTemplate` гуманоида. В коде сейчас
  временно существуют два класса `Character`: старый
  (`Witcher.Core/DAL/Entities/Character.cs`, привязан к `Creature`/`BodyTemplate`)
  и новый (`Wastelands.Service.Domain/Entities/Character.cs`, статы + `Skills`)
  — их предстоит свести в одну сущность при переработке.

### Навыки, способности и бой
- **Skill** — вид навыка персонажа/существа. Закрытый список, каждый навык
  привязан к конкретной характеристике.
  - Бросок навыка: 1к10. Результат 10 — «взрыв»: кидается ещё один к10, и его
    значение прибавляется к сумме; если и там выпало 10 — кидается ещё раз, и
    так далее. Результат 1 — тоже пересброс по той же цепочке «взрыва на 10»,
    но итоговая сумма считается отрицательной. К результату броска прибавляется
    значение навыка и значение управляющей им характеристики.
- **Ability** — способность существа/персонажа атаковать: число атак за ход,
  используемый при атаке `Skill`, число кубиков урона и модификатор к ним,
  виды и вероятность накладываемых эффектов, тип урона. Также указывает,
  каким скиллом из списка защищающегося можно противодействовать этой атаке.
  Аналог `Ability` для персонажей игроков — оружие (`WeaponTemplate`/`Weapon`).
- **DefensiveSkill** — навык, которым можно защищаться от атаки. Если у
  защищающегося такого навыка нет, вместо него используется значение
  характеристики, отвечающей за атакующий скилл.
- **Процесс атаки:**
  1. В бою участники ходят по очереди в порядке инициативы.
  2. Атака = бросок `Ability` (через её `Skill`) против броска `DefensiveSkill`
     защищающегося. Бросок атаки больше броска защиты → попадание.
  3. Если атака не прицельная — случайным броском определяется, в какую
     `CreaturePart` цели пришёлся удар.
  4. Бросок на размер урона.
  5. Из урона вычитается значение брони в той `CreaturePart`, куда пришёлся
     удар. Если броня полностью поглотила урон — атака не имела эффекта.
  6. Если урон не поглощён полностью — к остатку применяются модификаторы
     `EntityDamageTypeModifier` существа и модификаторы урона конкретной части
     тела.
  7. Если урон нанесён — рассчитываются возможные наложения `Effect` и
     `CritEffect`, а броня в этой части тела уменьшается на 1.
- **Effect** — негативный эффект/статус, накладывается и снимается по особым
  правилам, зависящим от конкретного эффекта.
- **CritEffect** — эффект особенно сильной атаки: возникает, если бросок атаки
  превысил бросок защиты на определённую величину. Влияет на характеристики
  существа/персонажа. Конкретный вид критического эффекта определяется
  величиной превышения атаки над защитой и типом части тела, в которую пришёлся
  удар (отсюда семейства `Simple/Difficult/Deadly/Complex` × тип части тела).
